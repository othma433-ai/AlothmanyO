# WA Al-Othmany Android v2.2 Real-Device Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a build-ready v2.2 source release with scan-only invite jobs, safer verified publishing, durable action phases/heartbeats, and stronger long-run navigation.

**Architecture:** Extend the existing Accessibility/Room design instead of replacing it. State transitions are persisted before risky UI actions; uncertain sends are verification-pending and never auto-resend.

**Tech Stack:** Kotlin, Android AccessibilityService, Room 2.8.5, Coroutines, Android Foreground Service, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-09-15-v2.2-real-device-reliability-design.md`

## Global Constraints
- No root requirement.
- No direct WhatsApp private database access.
- Every UI wait and retry is bounded.
- No automatic resend after an ambiguous Send click.
- Room data from v2.0/v2.1 must survive migration.
