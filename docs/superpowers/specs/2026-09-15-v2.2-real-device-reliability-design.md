# WA Al-Othmany Android v2.2 Real-Device Reliability Design

## Goal
Turn the v2.1 draft into a safer real-device automation release by fixing build blockers, separating invite scan from join, making publish recovery duplicate-safe, adding durable action phases and heartbeats, and strengthening group-list completion proof.

## Architecture
Keep Accessibility-first automation and Room as the source of truth. Add durable action phase/evidence fields rather than encoding state in free-form detail text. Treat ambiguous post-send states as verification-pending instead of retrying automatically. Add scan-only invite jobs that never click an invite action.

## Data model
Room schema v3 adds `phase`, `resultState`, `lastEvidence`, and `lastProgressAt` to action work, plus `lastProgressAt` to extraction jobs. Migrations preserve all v2 data.

## Invite flow
SCAN_INVITES opens each explicit invite URL, classifies the visible state, persists the classification, and performs no join click. JOIN keeps the same-node click chain and only marks success after a verified post-state.

## Publish flow
Capture exact-message count before send. After clicking Send, require composer clearing plus a newly observed exact message or another strong acknowledgement. If the click is accepted but delivery cannot be proven, persist `VERIFY_PENDING` and never auto-resend that item; recovery verifies first.

## Long-run reliability
Persist heartbeat/progress timestamps on every durable transition. Group sync requires repeated stable/bottom evidence instead of returning after a single failed scroll. Chat lookup gets a bounded rewind-and-retry pass.

## Verification
Pure Kotlin regression tests cover parser/classifier, send verification policy, and action retry decisions. Static project verification checks migration/version/action invariants and malformed diagnostics text. GitHub Actions remains the authoritative Android compile/test/APK build path when local Android SDK is unavailable.
